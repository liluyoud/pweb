Regra de aprovação

O status é calculado pela API: o usuário digita só as notas

Lançar notas

N1 e N2 (de 0 a 10)

Média

(N1 + N2) / 2

≥ 7

aprovado direto

< 7

faz a Prova Final (PF)

(média + PF) / 2

≥ 5 aprovado
< 5 reprovado

Enquanto falta alguma nota necessária, o status é cursando.
A regra mora em um lugar só: apps/api/src/regras/notas.ts
Controle Acadêmico · 6
Exemplo: N1 = 5 e N2 = 6 → média 5,5 → cursando até lançar a PF. PF = 7 → (5,5 + 7) / 2 = 6,25 → aprovado.
SEÇÃO 02

Conceitos fundamentais

Glossário · Web · Dados

Esta seção usa o glossário compartilhado (pweb/docs/glossario.md) como referência. Cada slide traz um ou dois termos com um exemplo do próprio projeto.

Cliente e servidor

Quase todo sistema web é dividido em duas partes: a analogia do restaurante

Usuário

O cliente no salão faz o pedido: “quero ver os alunos”

Site (web)

O garçom: anota e leva o pedido. Não cozinha!

API (Bun)

A cozinha: prepara a resposta

Banco SQLite

A despensa: onde tudo fica guardado

Front-end roda no navegador e apresenta a interface. Aqui: apps/web
Back-end roda no servidor e cuida das regras e dos dados. Aqui: apps/api
Controle Acadêmico · 8
E o cardápio que todos consultam? É o pacote packages/tipos, que define o formato de cada 'prato' (Aluno, Professor...).

HTTP: o idioma da web

Cada pedido do navegador para a API tem um método e um caminho

GET

Buscar dados

GET /api/alunos

POST

Criar um registro

POST /api/alunos

PUT

Atualizar um registro

PUT /api/alunos/7

DELETE

Excluir um registro

DELETE /api/alunos/7
HTTP é o “idioma” que o navegador e a API usam para conversar. O pedido vai com método, caminho e (às vezes) um corpo em JSON; a resposta volta com um status e um corpo.
Controle Acadêmico · 9
Mostre no navegador: abrir http://localhost:3333/api/alunos é um GET. Para POST, PUT e DELETE precisamos de um formulário, do Scalar ou do curl.

Status HTTP

O número que a API devolve dizendo como foi o pedido

2xx · deu certo

200 Deu certo

201 Criado com sucesso

204 Concluído, corpo vazio

4xx · problema no pedido

400 Pedido com problema (ex.: campo faltando)

404 Não encontrado

409 Conflito com o estado atual

5xx · erro no servidor

500 Algo quebrou dentro da API

No Acadêmico, a função error() do index.ts captura o erro e responde com uma mensagem amigável.

Controle Acadêmico · 10
Exemplos do projeto: criar aluno → 201; buscar aluno com id inexistente → 404; CPF repetido → 400 com a mensagem traduzida.

JSON: o formato da conversa

Texto para trocar dados, parecido com um objeto JavaScript

Ida: objeto → texto

JSON.stringify(dados) transforma o objeto em texto para enviar pela rede

Volta: texto → objeto

await resposta.json() no site e await req.json() na API

API, endpoint e REST

O endereço diz o quê; o método diz a ação

API

Application Programming Interface: o conjunto de operações que um cliente pode chamar pela rede. Métodos e caminhos formam o contrato.

Endpoint / rota

Uma operação identificada por método + caminho, como GET /api/alunos.

GET /api/alunos/7

a ação: buscar

recurso
a coleção de alunos

:id
qual aluno (parte variável)

Esse padrão de endereços se chama REST. O mesmo vale para professores, disciplinas e matrículas.

Porta, proxy e CORS

Como o site (5173) conversa com a API (3333) sem configuração extra

Navegador

pede /api/alunos a localhost:5173

Vite (proxy)

repassa tudo que começa com /api

API Bun

responde em localhost:3333

Porta

Número que diz qual serviço recebe a conexão: 5173 (site) e 3333 (API).

Proxy

Intermediário que encaminha pedidos. O Vite faz isso durante o desenvolvimento.

CORS

Regra do navegador entre origens diferentes (protocolo + host + porta). Com o proxy, tudo parece ter a mesma origem.

Controle Acadêmico · 36
PK = chave primária (o id). FK = chave estrangeira: aponta para a PK de outra tabela. Relação 1 para N entre alunos e matrículas (o mesmo vale para professores e disciplinas).

Criando a tabela de alunos

O SQL que define colunas, tipos e restrições

PRIMARY KEY AUTOINCREMENT

O banco gera o id sozinho: 1, 2, 3...

NOT NULL

Campo obrigatório: o banco recusa vazio (nulo).

UNIQUE

Não aceita repetido: dois alunos com o mesmo CPF ou matrícula.

foto TEXT

Sem NOT NULL: aceita nulo quando não há foto.

Controle Acadêmico · 37
A tabela professores segue o mesmo modelo, com titulacao e graduacao no lugar de matricula.

Disciplinas e matrículas

Restrições que protegem os dados mesmo se a API errar

REFERENCES

Chave estrangeira: o aluno_id precisa existir em alunos.

CHECK

Notas entre 0 e 10. Em disciplinas: carga_horaria > 0.

UNIQUE (aluno, disciplina, semestre)

Impede matricular o mesmo aluno duas vezes na mesma disciplina e semestre.

Controle Acadêmico · 38
Por causa das FKs, não dá para excluir um aluno que tem matrículas: o banco impede e a API traduz a mensagem.

Conexão com o SQLite

Sem instalar servidor: o próprio Bun lê e escreve no arquivo

Sem PRAGMA foreign_keys = ON, o SQLite aceitaria matrícula de aluno inexistente.
CREATE TABLE IF NOT EXISTS é ignorado se a tabela já existe: por isso roda toda vez que a API liga.
Por isso também: mudou uma tabela? Apague o .sqlite para recriar.

O SQLite diz…A API responde…
